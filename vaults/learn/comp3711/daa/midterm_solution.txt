Let m denote the number of distinct numbers in A[1..n]. The algorithm
constructs a sorted array B[1..n] of the distinct numbers in A[1..n].
Each entry of B contains a key and a frequency. The key is the cor-
responding number in A[1..n]. The frequency is the frequency of that
number in A[1..n]. The entries in B are sorted in increasing order of
keys. The construction of B works as follows.
The sorted array A[1..n] appear as m contiguous subarrays, each con-
taining duplicates of a distinct element. That is, A[1..k1 ] contains the
duplicates of the smallest distinct element, A[k1 +1..k2 ] contains the du-
plicates of the second distinct element, . . ., and A[km−1 + 1..n] contains
the duplicates of the largest distinct element. Our task is to determine
m, the values of k1 , k2 , . . . , km−1 , and the distinct elements.
Clearly, B[1] should store A[1] as the key. We determine the index k1
in O(log n) time by calling the following pseudo-code Search(A, p, r, x).
The precondition for invoking Search(A, p, r, x) is that A[p] = x and
p ≤ r. Search determines the index k ∈ [p, r] such that A[k] = x, and
either k = r or A[k + 1] > x.
     Search(A, p, r, x)
       if p = r or A[r] = x then
          return r
       else
          q ← b(p + r)/2c
          if A[q] = x then
             if A[q + 1] > x then
                return q
             else
                return Search(A, q + 1, r, x)
             end if
          else
             return Search(A, p, q − 1, x)
          end if
       end if
We make the top level call Search(A, 1, n, A[1]) to obtain k1 . Since
each recursive call of Search halves the input range of indices, and
only O(1) work is done at each recursion level, the running time of
Search(A, 1, n, A[1]) is O(log n). Then, the frequency to be stored at

B[1] is k1 .
The second contiguous subarray starts at A[k1 + 1]. So we make the
top level call Search(A, k1 + 1, n, A[k1 + 1]) to obtain k2 in O(log n)
time. Afterwards, we store A[k1 + 1] as the key value and k2 − k1 as
the frequency at B[2].
We continue in the above manner until some top level call Search(A, ki +
1, n, A[ki + 1]) outputs n as the returned value. When this happens, we
have determined the last contiguous subarray. So m = i. We store the
key A[ki + 1] and its frequencey n − ki at B[i]. Then, we stop.
The determination of each entry of B takes O(log n) time. There are
m = Θ(log n) entries to be determined. So the total running time is
O(log2 n).

First, for i = 1 to n/ log2 n, sort subarray A[1+(i−1) log2 n..i log2 n]
in increasing order, which takes O(log n · log log n) time. Let Bi
be an array of log2 n ordered pairs such that Bi [j] = (i, A[(i −
1) log2 n + j]). Summing over i ∈ [1, n/ log2 n], the total time is
O(n log log n).
Second, initialize a heap H that consists of the first ordered pair in
every Bi . Initialize a pointer pi = 1 + (i − 1) log2 n for each i ∈
[1, n/ log2 n]. The heap follows the min-heap order on the second
component of each ordered pair. This requires n/ log2 n insertions,
which takes O((n/ log n) · log n) = O(n) time.
Third, perform an extract min on H. Let (i, v) be the ordered pair
obtained. We output v. Increment pi . Insert Bi [pi ] into H. If
we have output fewer than dlog2 ne elements so far, we repeat the
third step. This step requires dlog2 ne extract mins and insertions.
Therefore, the total time spent on the third step is O(log n·log n) =
O(log2 n) time.
In summary, the running time of the first step dominates.
